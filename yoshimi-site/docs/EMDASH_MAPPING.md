# 元資料の内容をどう取り入れたか

元資料: Google ドキュメント「【文字起こし】WordPressはもう古い。Cloudflareの無料CMS『EmDash』がAI時代の正解だった」
（KEITO【AI&WEB ch】の解説動画、2026-10-18 公開、の文字起こしと要点まとめ）

資料の主張は「これからのサイトは、AI エージェントが読み書きできる前提（AI ネイティブ）で作るべきで、その代表が EmDash」というものです。
このリニューアル版では、資料に出てくる要素を次のように取り入れました。

## 1. EmDash そのもの

| 資料のポイント | このサイトでの扱い |
|---|---|
| Cloudflare 製のオープンソース CMS（MIT ライセンス、v1.0 は 2026-09-28） | EmDash 1.3 系で構築。テンプレートは公式 `marketing`（Cloudflare 版）を拡張 |
| Cloudflare の無料枠（Workers・D1 など）で動き、費用は基本ドメイン代だけ | `wrangler.jsonc` で Workers・D1・R2 を使う構成。有料機能（サンドボックス）は無効のまま |
| TypeScript と Astro で動く（PHP ではない） | Astro 7 ＋ TypeScript。すべてのページはサーバーで描画 |
| WordPress に近い管理画面（カスタム投稿・メディア・メニュー・ウィジェット・カテゴリー・タグ・投稿者・スラッグ・公開切り替え） | 管理画面は `/_emdash/admin`。カスタム投稿として「メンバー」「お知らせ」、分類として「お知らせの種類」、メニュー 4 つを用意。ブロックとコレクションのラベルは日本語化 |
| 公式サイトの Playground で操作感を試せる | 導入前の体験用。docs/AI_OPERATIONS.md に案内 |

## 2. AI ネイティブ（MCP 標準搭載）

| 資料のポイント | このサイトでの扱い |
|---|---|
| 人間用の管理画面と、AI 用の窓口（MCP）が同じ入口 | EmDash 標準の MCP（`/_emdash/api/mcp`）をそのまま使う。記事・メディア・メニュー・スキーマ・設定など 80 近い操作ができる |
| Claude Code や ChatGPT のコネクタとして接続し、チャットで操作 | Claude Code（PC）と Claude アプリのカスタムコネクタ（スマホ）の接続手順を docs/AI_OPERATIONS.md に記載。OAuth ＋ パスキーでログイン |
| 大枠は AI に作らせ、最後の微調整だけ人が管理画面で行う | 運用ルールとして明文化（AI は下書きまで、公開は人が確認してから）。`.claude/skills/yoshimi-site-ops/` に手順書 |
| 本文を HTML ではなく構造化データで持つので AI が扱いやすい | メンバーは「発信テーマ」「イメージカラー」「X の URL」などの項目に分け、会社概要も「項目名と内容」の組で持つ（文章の中に埋め込まない） |
| 「スマホに話しかけるだけでサイトが更新される」 | Claude アプリ（スマホ）にこのサイトの MCP をコネクタとして追加すれば、話しかけて更新できる |

さらに、サイトを「読む側」の AI 向けにも次を足しました（資料の考え方を訪問者側にも広げたもの）。

- `/llms.txt`: メンバー・お知らせ・ページの要約を、CMS のデータから毎回自動で作る
- WebMCP: ブラウザに組み込まれた AI エージェントが、サイト内検索をツールとして呼べる（対応ブラウザのみ）
- 構造化データ（JSON-LD）: 会社（Organization）とお知らせ記事（BlogPosting）

## 3. 実演デモに相当するもの

| 資料のデモ | このサイトでの相当物 |
|---|---|
| ① 書籍の URL と画像を渡して「サイトの書籍欄に追加して」と 4 行で頼むと、要約・画像・リンク・カスタム投稿の登録まで自動 | 「配信告知の URL とサムネイルを渡して、お知らせに追加して」「新メンバーの立ち絵とプロフィールを渡して、メンバーに追加して」。頼み方の例は docs/AI_OPERATIONS.md |

| パスキー認証の管理画面 | 管理画面のログインはパスキー。PC とスマホの 2 台で登録する手順を README に記載 |

## 4. WordPress との比較

資料の比較表は、訪問者向けに「このサイトの仕組み」ページ（`/ai-native`）で言い換えて紹介しています。

| 項目 | WordPress | EmDash（このサイト） |
|---|---|---|
| 設計の前提 | 2003 年ごろの Web | AI エージェントがいる今の Web |
| 動かす場所 | レンタルサーバー | Cloudflare の分散基盤（サーバーレス） |
| 技術 | PHP | TypeScript・Astro |
| 本文 | HTML 中心 | 構造化データ |
| プラグイン | 本体と同じ場所で動く | 隔離して動かせる（※有料プラン） |
| AI 連携 | 後付けのプラグイン | MCP を標準搭載 |
| 保守 | 本体・テーマ・プラグイン・PHP・サーバーの 5 つを自分で更新 | ほぼ不要 |
| 拡張機能 | 数万件 | まだ少ない（AI と一緒に作る） |

## 5. 資料どおりにしていないところ

- **プラグインの隔離実行**: 有料プラン（月 $5〜）が必要なため無効のまま。公式のフォームプラグインは「信頼済みプラグイン」として本体と同じ場所で動く
- **WordPress からの移行機能**: 現行サイト（yoshimimusubi.com）は 2026-10-27 時点で名前解決できず、中身を確認できなかった。
  現行サイトが WordPress なら、WordPress からエクスポートした WXR ファイル（または WordPress の REST API）を、管理画面のインポート機能で取り込める
  （取り込んだあと、お知らせ・固定ページへの振り分けを AI に頼む）
- **公式プラグインマーケットからのインストール**: 今はフォームプラグインだけを設定ファイルで入れている。YouTube 埋め込み（`@emdash-cms/plugin-embeds`）などは必要になったら追加する

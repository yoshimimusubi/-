# PC ⇔ スマホ タスク相互管理 要件定義

## 1. 目的

PC（ローカルの Claude Code / Claude デスクトップアプリ）とスマホ（Claude アプリの Code タブ・Dispatch）の
どちらで始めたタスクも、もう一方から **状態確認・続行・完了** できるようにする。

## 2. 全体構成（3層）

| 層 | 方向 | 仕組み | 用途 |
|---|---|---|---|
| 実行の橋渡し① | PC → スマホ | **Remote Control**（`claude remote-control`） | PC で途中までやった作業を、外からスマホで続きを頼む・承認する |
| 実行の橋渡し② | スマホ → PC | **クラウドセッション（claude.ai/code）＋ `claude --teleport`** | 外出先で新規タスクを立ち上げ、帰宅後に PC へ引き取る |
| 共通の台帳 | 双方向 | **GitHub 上の `TASKS.md`** | 「いま何が進行中か」を PC・スマホ・クラウドで一致させる |

使い分けの原則（参考記事の運用に準拠）:

- **途中までやりかけた作業** → スマホの Code タブから既存セッション（緑マーク＝アクティブ）に続きを頼む
- **新しく外から頼みたい作業** → Dispatch またはスマホの Code タブから新規セッション
  （既存セッションに別件を混ぜるとコンテキストが崩れるため、別件は必ず新規セッション）

## 3. 前提条件

- PC の Claude デスクトップアプリ / Claude Code CLI とスマホの Claude アプリが **同一アカウント（同一メールアドレス）** でログイン済み
  - つながらない原因の大半は「アカウント違い」か「アプリのバージョンが古い」。まずここを確認する
- claude.ai/code で GitHub 連携済みで、本リポジトリ（`yoshimimusubi/-`）にアクセスできる
- 有料プラン（Claude Code が使えるプラン）に加入済み
- PC 側に `git` と `claude` コマンドが入っている

## 4. 機能要件

| ID | 要件 | 実現手段 |
|---|---|---|
| FR1 | PC の作業をスマホから続行・承認できる | Remote Control |
| FR2 | スマホから PC 上で新規セッションを開始できる | `claude remote-control`（サーバーモード）を PC で常駐 |
| FR3 | スマホで始めたクラウド作業を PC に引き取れる | GitHub 連携済みクラウドセッション＋`claude --teleport` |
| FR4 | 全タスクを 1 つの台帳で管理する | `TASKS.md`（ID / タイトル / 状態 / 実行場所 / 最終更新 / 次の一手） |
| FR5 | セッション開始時に台帳を最新化して要約表示する | SessionStart フック（`.claude/hooks/task-sync-start.sh`） |
| FR6 | 作業開始・中断・完了時に台帳を更新して commit / push する | `CLAUDE.md` の運用ルール＋ `/task-add` `/task-status` `/task-done` |
| FR7 | クラウドセッションのブランチ上で更新された台帳も PC から見える | SessionStart フックが `origin/claude/*` ブランチの TASKS.md も走査して表示 |
| FR8 | 長時間タスクの完了時・判断待ち時にスマホへ通知する | Claude アプリのプッシュ通知（Remote Control / クラウドセッション標準機能） |

## 5. 非機能要件

- **可用性**: 作業中は PC をスリープさせない。ログイン時に `claude remote-control` を自動起動する
  （Remote Control のプロセスが終了するとスマホからはオフライン扱いになるため）
- **整合性**: `git pull` で台帳が競合した場合、自動で片方を採用しない。両方の内容を提示してユーザーに確認する
- **セキュリティ**: 台帳に API キー・パスワード・個人情報（顧客名・メールアドレス・金額明細など）を書かない。
  詳細は各セッション内にとどめ、台帳には「何の件か」が分かる最小限の表現だけ書く
- **軽量性**: SessionStart フックは失敗してもセッション開始を妨げない（ネットワーク不通時はスキップ）
- **可搬性**: macOS（launchd）と Windows（タスクスケジューラー）の両方で常駐設定を用意する

## 6. 台帳（TASKS.md）仕様

| 列 | 内容 | 例 |
|---|---|---|
| ID | `T-YYYYMMDD-NN` | `T-20260927-01` |
| タイトル | 何の件か（個人情報なし） | 秋講座 決済金額の確認 |
| 状態 | `todo` / `doing` / `waiting` / `done` | `doing` |
| 実行場所 | `PC` / `Cloud` / `Dispatch` | `Cloud` |
| 最終更新 | JST `YYYY-MM-DD HH:MM` | `2026-09-27 14:30` |
| 次の一手 | 次に誰が何をするか | 返金案内メールの下書き確認（本人） |

- `done` になったタスクは月ごとに `## Archive YYYY-MM` へ移動する
- `waiting` は「ユーザーの判断・返信待ち」。スマホで最初に見るべき行

## 7. 運用フロー

1. **セッション開始**: フックが `git pull` → 台帳の `doing` / `waiting` とクラウドブランチ上の進行中タスクを要約表示
2. **作業開始**: 該当タスクを `doing` にし、実行場所を記録（新規なら `/task-add`）
3. **中断・終了**: 状態と「次の一手」を更新して commit & push
4. **完了**: `/task-done <ID>` で `done` にして commit & push
5. **スマホから確認**: Claude アプリの Code タブで任意のセッションを開き `/task-status`、
   または GitHub アプリで `TASKS.md` を直接見る

## 8. 完了条件（受け入れ基準）

- [ ] スマホの Claude アプリの Code タブにこの PC が表示され、セッションを開始できる
- [ ] PC で始めたセッションの続きをスマホから送れ、PC のターミナルにも反映される
- [ ] スマホ（クラウド）で `/task-add` したタスクが、PC で次にセッションを開いたときに表示される
- [ ] PC で `/task-done` したタスクが、スマホ側の `/task-status` で `done` になっている
- [ ] PC 再起動後、ログインするだけで Remote Control が自動で立ち上がる

## 9. 対象外・既知の制約

- 既存のローカルセッションをクラウドへ「押し出す」ことはできない（引き取りはクラウド → PC の一方向）
- PC がスリープ・シャットダウン中は Remote Control 経由の作業はできない（クラウドセッションは動く）
- クラウドセッションは作業ブランチ（`claude/*`）に push するため、台帳の変更が `main` に入るのは PR マージ後。
  それまでは FR7 のブランチ走査で可視化する

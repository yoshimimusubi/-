# Antigravity でテスト環境を動かして確認する

PC の中に、本番と同じしくみ（Cloudflare Workers）を再現したテスト環境を立ち上げ、
Antigravity のエージェントとブラウザでサイトを確認するための手順です。

- インターネットには公開しません（見られるのはその PC の中だけ、`http://localhost:8787`）
- Cloudflare のアカウントやログインは不要です
- お問い合わせフォームは、Cloudflare が用意しているテスト用のボット判定キーで動きます。送信したメールは実際には届かず、PC の中に `.eml` ファイルとして保存されます

作成時点のクラウド環境で、同じ手順（`npm ci` → テスト → ビルド → `npm run preview` → `npm run smoke`）がすべて通ることと、
送信されたメールの中身が正しいことを確認済みです。クラウドから確認できなかったのは、ボット判定（Turnstile）の画面表示だけです。

## 0. Antigravity の安全設定（手動・3 分）

Antigravity のエージェントは、ターミナルのコマンド実行とブラウザ操作ができます。
読み込んだページやファイルに紛れ込んだ指示で勝手に動かされる手口（プロンプトインジェクション）があるため、先に次を確認してください。
設定の名前は版によって違う場合があります。

- [ ] **ダウンロードフォルダの中のフォルダを開かない**（`docs/security/` の点検で扱った乗っ取り手口の対策と同じ）
- [ ] ターミナルコマンドの自動実行をオフにする（実行のたびに確認する設定）
- [ ] エージェントの変更をそのまま適用せず、確認してから適用する設定にする
- [ ] ブラウザで開いてよい URL を指定できる場合は `http://localhost:8787` だけにする
- [ ] このフォルダに、本物の API キー・パスワード・顧客情報を置かない（`.dev.vars` に入れるのはテスト用の値だけ）

## 1. テスト用のフォルダを用意する（手動・2 分）

今の作業フォルダを汚さないように、テスト用のフォルダを別に作ります（git の worktree）。
PC にあるこのリポジトリ（`yoshimimusubi/-`）のフォルダでターミナルを開き、次を実行します。

```bash
git fetch origin claude/yoshimi-site-secure-rebuild
git worktree add ../yoshimi-site-test claude/yoshimi-site-secure-rebuild
```

できた `yoshimi-site-test` フォルダを Antigravity で開きます（File → Open Folder）。

PC にまだリポジトリがない場合は、ダウンロードフォルダ以外の場所で次を実行します（非公開リポジトリなので GitHub へのログインが必要です）。

```bash
git clone -b claude/yoshimi-site-secure-rebuild https://github.com/yoshimimusubi/-.git yoshimi-site-test
```

## 守ってほしいこと
- 最初に OS・Node.js と npm のバージョン・git のブランチを確認し、やることの計画を見せて私の承認を取ってから始める

- ファイルは変更しない（.dev.vars の作成と、test-results/ へのスクリーンショット保存だけは可）。問題を見つけたら直さずに報告し、直し方の提案をする

- ブラウザで開くのは http://localhost:8787 だけ。127.0.0.1 ではなく localhost で開く（お問い合わせの送信元の確認に使っているため）

## 3. 自分の目で見てほしいところ

エージェントの確認とは別に、次の点は人が見て判断してください。

- [ ] トップの第一印象（色・フォント・りんごのイラスト・キャッチコピー）が会社のイメージと合っているか

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| `npm ci` で `EBADENGINE` などのエラー | Node.js が古い。22.22 以上（LTS 版）を入れる |
| Windows で `cp` が使えない | PowerShell では `Copy-Item .dev.vars.example .dev.vars` |
| お問い合わせの送信で `Forbidden`（403） | `127.0.0.1` で開いている。`http://localhost:8787` で開き直す |
| 「確認が完了しませんでした」の画面 | `.dev.vars` がない、またはボット判定のスクリプトが読み込めていない（広告ブロッカーや社内のネットワーク制限）。コンソールのエラーを確認 |
| 「しばらくしてからお試しください」の画面 | 送信回数の制限（60 秒に 3 回）。1 分待つ |
| ポート 8787 が使用中 | `npx wrangler dev --port 8790` で起動し、`.dev.vars` の `SITE_ORIGIN` を `http://localhost:8790` に変え、`npm run smoke -- http://localhost:8790` で確認 |
| `npm run smoke` が「接続できません」 | 先に別のターミナルで `npm run preview` を起動しておく |

## 終わったら

- テスト用のフォルダは、元のリポジトリのフォルダで `git worktree remove ../yoshimi-site-test` を実行すると消せます
- 結果（エージェントの報告とスクリーンショット）を Claude に渡してもらえれば、直す点を反映します

## この先：インターネット上のテスト環境（任意）

社内の人や関係者にスマホから見てもらう段階になったら、Cloudflare 上に「テスト用の公開環境」を別に作れます。
その場合は、検索エンジンに載らない設定（noindex）と、見られる人を限定する設定（Cloudflare Access）を付けてから公開します。
Cloudflare のアカウントができたら、その設定を用意します。
